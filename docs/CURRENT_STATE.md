# SlackerKing 当前现状

## 一句话判断

项目已经从“单文件黑色幽默原型”推进到“可持续扩内容的短局叙事策略小品”阶段。

当前版本的强项不再只是能玩，而是已经具备：

- 明确的三段式核心循环：晨间事件、午后行动、夜间结算。
- 可读的风险反馈与夜间解释层。
- 有方向感的四派系路线骨架与持续角色。
- 基础留存系统：自动续档、王朝档案、图鉴、里程碑、最近几局复盘。

当前最主要的不足已经不是“基础框架不稳”，而是“阶段 3 的中局内容厚度仍然不够”，也就是路线虽然可见，但真正能拉开中局差异的派系事件链还需要继续扩。

## 当前产品认知

当前产品更接近“高复玩、短局、带黑色幽默味道的轻策略叙事游戏”，而不是重度数值模拟器。

它的核心体验已经比较清晰：

- 玩家需要在有限精力和行动力下维持四项国家资源与个人压力。
- 晨间选择开始承担路线押注和政治后果。
- 午后地点不再只是 flavor，而是会持续产生日后政治后果和后续事件。
- 夜间结算承担风险兑现、路线后遗症表达和复盘解释。
- 死亡后，档案系统会把这局转化为下一局的目标感，而不是纯重开。

## 当前实现到哪一步了

### 阶段 1：信息可读性

这一阶段已经闭环完成。

- 顶部风险徽记、资源趋势、夜间汇总已经接入。
- 情报暗室已具备风险压制与解释反馈。
- 夜间结算和败局页已经能解释“发生了什么”和“为什么会输”。

### 阶段 2：数值职责重构

这一阶段也已经闭环完成。

- 资源、精力、压力、午后地点的职责已被重新定义。
- 晨间选项已经有明显的低/中/高代价分层。
- 午后地点已经形成差异化定位，而不是同质化按钮。

### 阶段 3：派系与事件链扩充

这一阶段已经打出稳定骨架，但仍在继续扩内容。

- 四条核心路线已经可见：旧贵族、军方、商会、外邦。
- 路线权重已经能真实影响晨间事件出现概率。
- 持续角色、角色后续、路线升级事件、午后衍生事件都已接入。
- 派系化夜间风险已经存在，路线后遗症能被系统表达出来。

当前仍然缺的是：

- 更厚的中局分岔内容。
- 每条路线再多一层真正改变打法的升级链。
- 更多能把同一路线分出不同子走法的事件组合。

### 阶段 4：重玩驱动与基础功能

这一阶段已经从“规划”进入“持续补强”。

目前已经落地：

- 当前局自动保存与继续游戏。
- 王朝档案常驻入口。
- 死法图鉴与统治原型图鉴。
- 王朝里程碑。
- 最近几局摘要与路线复盘。
- 败局页的“本局新达成”即时反馈。

换句话说，阶段 4 里“基础留存能力”已经成立，但后续还可以继续做演出层和成就感强化。

## 当前代码结构认知

当前项目的结构已经比较清楚，接手时可以按下面理解：

- src/data/gameContent.js：内容与数值源头。资源元数据、派系元数据、角色元数据、晨间事件、午后地点、夜间风险都集中在这里。
- src/logic/engine/gameEngine.js：单局规则核心。状态推进、晨间结算、午后访问、夜间风险、败局判定、路线总结都在这里。
- src/logic/hooks/useGameSession.js：React 层的会话编排。负责把引擎状态推进、自动续档、败局入档、界面状态串起来。
- src/logic/storage/currentRun.js：当前局存档。
- src/logic/storage/runRecords.js：长期档案存档，负责最近几局、图鉴、里程碑这类跨局记录。
- src/view/components：桌面侧栏、顶部栏、日志栏等信息组件。
- src/view/screens：晨间、午后、夜间、败局等阶段页面。

一个接手者可以把它简单理解为：

- gameContent.js 决定“有什么内容”。
- gameEngine.js 决定“规则怎么结算”。
- useGameSession.js 决定“这一局怎么跑起来”。
- storage 目录决定“哪些信息要跨刷新或跨局保留”。
- view 目录决定“这些信息怎么被玩家看到”。

## 当前最值得注意的实现约定

- 单局推进的可靠边界在 engine，不要把核心规则判断写回 React 组件。
- useGameSession 使用稳定 state ref 做推进，避免依赖 setState updater 的副作用返回值。
- 午后后续与事件链优先使用字符串 aftermath flag，而不是数值 visit counter，以免被夜间 flag 自增逻辑误伤。
- 路线内容要靠 factionId 权重提升，不要只做条件放行，否则容易被高权重 follow-up 事件饿死。
- 当前长期留存基本都建立在 runRecords 上；如果要继续扩图鉴、里程碑、最近几局，优先沿这条线加，而不是新开一套存档。

## 当前项目风险与短板

### 内容层短板

- 中局路线差异还不够厚。
- 虽然已经有派系升级事件，但还没到“每局都能明显玩出不同政治故事”的密度。

### 系统层短板

- 长期留存已经有了，但演出层还比较轻。
- 新达成反馈目前只在败局页出现，还没形成更强的即时奖励感。

### 文档层短板

- 阶段规格文档是分阶段的，适合设计推进。
- 但如果只是想快速理解“项目现在是什么”，应该先看这份文档，再回到路线图和阶段规格。

## 建议的阅读顺序

如果现在要接手项目，推荐按下面顺序阅读：

1. 先看本文件，建立整体现状认知。
2. 再看 docs/IMPLEMENTATION_PLAN.md，理解阶段推进和剩余缺口。
3. 再看 docs/PHASE_3_FACTION_SPEC.md，理解当前最值得继续扩的内容方向。
4. 最后回到 src/data/gameContent.js 和 src/logic/engine/gameEngine.js，对照文档看现有实现。

## 当前建议的下一步

如果继续按性价比推进，优先级建议是：

1. 继续扩阶段 3 的中局派系升级链，让每条路线再多一层真正改变打法的内容。
2. 再补阶段 4 的演出强化，比如里程碑首次达成的更强反馈、档案排序和更明显的目标提示。
3. 在内容厚度足够后，再考虑音效、演出和更完整的结局层包装。
